# الحد اليومي — النقطتان الثانية والثالثة

التعديلات جاهزة محلياً فقط. نفّذ بالترتيب:

1. افتح SQL Editor في مشروع سند.
2. انسخ كامل migrations/202610050001_ai_daily_quota.sql إلى استعلام جديد، ثم Run. الملف ينشئ جدول sanad_ai_requests ودالة sanad_ai_quota فقط ولا يعدّل بيانات المحادثات أو المستخدمين الموجودة.
3. افتح Edge Functions > sanad-ai > Code واستبدل الكود بالكامل بمحتوى functions/sanad-ai/index.ts المحدث، ثم Deploy.
4. أبقِ Verify JWT with legacy secret معطلاً كما في الخطوة الأولى؛ جلسة المستخدم يتم التحقق منها داخل الدالة.
5. SUPABASE_SERVICE_ROLE_KEY يبقى في بيئة الخادم الافتراضية فقط. لا تضفه إلى التطبيق ولا ترسله في المحادثة.
6. أعد تشغيل التطبيق المعدل. افتح المساعد وتحقق من ظهور الرصيد ثم أرسل رسالة؛ يجب أن يزيد المستخدم بمقدار واحد وتنقص المتبقية بمقدار واحد عند نجاح الرد.
7. الحساب نفسه على جهاز آخر يشترك في الرصيد. يتجدد اليوم عند منتصف الليل بتوقيت بغداد، دون الاعتماد على ساعة الجهاز.
8. أخطاء المزوّد والردود الفارغة لا تُحتسب. إذا انقطع تنفيذ الخادم يُحرّر الحجز المعلّق بعد 120 ثانية عند الاستعلام التالي. تُحتسب الإجابة التي أنشأها المزوّد وأكّدها الخادم حتى لو انقطع اتصال الهاتف بعد ذلك.

هذه الخطوة تبدأ عداداً سحابياً جديداً؛ لا تنقل العداد المحلي القديم لأنه غير موثوق.

لا حاجة إلى تعطيل RLS أو إنشاء سياسة تسمح للتطبيق بالكتابة في جدول الاستهلاك. الجدول والدالة محجوبان عن anon وauthenticated؛ الاستخدام عبر الدالة الموثّقة على الخادم فقط.

لم يتم تنفيذ SQL أو اختبار الدالة على قاعدة البيانات الفعلية بواسطة Codex. لا تنتقل إلى بقية النقاط قبل تأكيد تطبيق SQL ونشر الدالة وتجربة الرصيد.
